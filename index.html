Kiến trúc AI-Native

Từ Legacy Gemini → Enterprise AI Architecture

❌ Trước đây (Legacy)

  • Gọi trực tiếp Google Gemini API từ Controller
  • Trả text tự do, không kiểm soát hallucination
  • Tự bịa điểm xác suất (PotentialScore)
  • Lưu raw prompt/response vào database
  • Thiếu kiểm tra quyền dữ liệu server-side
  • Gửi PII (email, SĐT) sang model AI

✅ Hiện tại (AI-Native)

  • Model Gateway IAIModelClient — DeepSeek V4 flash
  • Server-driven Grounding: Server tự sinh context, filter TenantId + ACL
  • Strict JSON Schema: Output cấu trúc chặt chẽ, có sourceIds
  • Abstain: Từ chối trả lời khi thiếu bằng chứng
  • Human-in-the-loop: AI tạo Draft → Người duyệt → Áp dụng
  • Không bao giờ gửi PII sang model

Check-in AI Evaluator

📊 Đánh giá check-in khách quan

  • So sánh tiến độ kỳ vọng vs tiến độ thực tế theo lịch deadline
  • Áp dụng Rubric định lượng + định tính có phiên bản (Versioning)
  • AI sinh nhận xét và điểm đánh giá Draft
  • Quản lý xem, chỉnh sửa, phê duyệt hoặc từ chối

🔐 Confidence Score

Tính điểm tự tin 4 yếu tố:

  • 40% Coverage — Độ phủ dữ liệu check-in
  • 25% Authority — Quyền hạn người check-in
  • 20% Consistency — Tính nhất quán lịch sử
  • 15% Freshness — Độ mới dữ liệu

✅ Cải tiến so với trước

Quản lý chấm điểm thủ công, chủ quan
→ AI đối chiếu dữ liệu, rubric chuẩn hóa
Không có thang đo, mỗi người chấm khác nhau
→ Rubric versioned, nhất quán toàn hệ thống
Mất 30+ phút/nhân viên để đánh giá
→ AI sinh draft 3-5 giây, quản lý chỉ cần duyệt

Chức năng KPI/OKR nổi bật

🔄 State Machine KPI

Vòng đời chặt chẽ: Draft → Pending → InProgress → Completed / Failed / Rejected. Chuyển trạng thái có kiểm soát quyền.

⚖️ Phân bổ trọng số

KPI giao theo phòng ban hoặc cá nhân với Weight (trọng số). Tổng trọng số kiểm tra 100% trước khi xác nhận.

🔗 Liên kết chiến lược

OKR liên kết Sứ mệnh → KPI liên kết OKR → Task liên kết KPI. Truy vết ngược từ task đến sứ mệnh.

👁️ Employee Tracking

🏅 Quy trình duyệt kết quả

Draft → Submitted → Director Reviewed. 3 cấp duyệt, tính thưởng sau khi giám đốc xác nhận.

Bảo mật & Phân quyền

🔐 RBAC — 60 Permissions

  • 5 vai trò: Super Admin, Admin, Director, Manager, Employee
  • 60 quyền hạn chi tiết (granular permissions)
  • [HasPermission] filter trên mọi Controller
  • PermissionClaimsTransformation nạp quyền vào Claims

🛡️ Row-Level Security (RLS)

  • SQL Server RLS + Session Context
  • 57 bảng có filter/block predicates
  • Tenant isolation: mỗi doanh nghiệp chỉ thấy dữ liệu mình
  • Ngay cả DBA cũng không bypass được khi query

📋 Audit Log

Ghi vết: hành động, thực thể bị tác động, IP, thời gian, người thực hiện. Phục vụ bảo mật và tuân thủ quy định.

🔑 Authentication

  • Cookie Authentication + Google OAuth2
  • Quên mật khẩu: token 1 lần + rate limiter
  • Mã hóa mật khẩu BCrypt
  • Session timeout + CSRF protection
